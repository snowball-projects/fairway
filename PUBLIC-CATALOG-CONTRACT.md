# Public native catalog contract

SQLite is the sole maintained facility/course authority. Only the sole writer's
reviewed generated `data/catalog-release/manifest.json` and `catalog.json.gz` are
adopted as public build inputs. Their release identity is recorded with the final
release evidence; generated bytes are never hand edited. Private SQLite, recovery
SQL, retained documents and source-control records are not public browser assets.

The envelope uses `format_version:2`, native `schema:5`, `revision`, closed binary
SHA-256 `catalog_release_key`, facilities, courses, shared destinations,
relationships, public provenance, source licenses, qualification and authority.
The manifest also binds compressed and raw SHA-256, byte lengths and row counts.
An old schema or a mismatched release fails closed without fallback.

Each facility, course, component and round owns its own optional observations.
All ten domain arrays are present: physical characteristics, amenities, practice,
services, policies, operating periods, accessibility, prices, architecture and
quality ratings. Empty arrays mean no recorded observation; nullable fields mean
unknown. Facility observations never silently become course facts. Architecture
credits retain nullable roles and years. Prices retain dated product, currency,
basis, unit, audience, residency, day/time and prerequisite conditions. These are
not current quotes, comparable price rankings, bookings or live availability.
Quality ratings remain empty; tee difficulty measures playing difficulty only.

Every observation retains its source envelope, exact subject scope, dates,
status, conflict, qualifications, license and attribution. Public note provenance
contains IDs only. Raw groups, note bodies, captures and local filesystem pointers
remain private evidence and never fill missing operational fields. Remaining
unmapped evidence is not represented as standardized data.

The Pages builder emits an explicit allowlist of public assets, a hash-named native
JSON catalog and a small project-relative manifest. Browser modules validate full
relationship and observation bindings. CI checks generated hashes, invokes that
same browser validator on the complete real catalog and compares two static builds.
No browser SQLite engine or editable JSON authority is introduced.

The builder also emits a derived, hash-named initial map index (`map_format:1`),
bound by that manifest to the complete catalog checksum, revision, release key and
counts. Its facility tuples retain only ID, name, state, city and map point; state
geometry retains existing search fitting. It carries no course facts. The browser
checks its hash, length, identity, counts and map shapes before drawing/searching.
Opening a course view requests the complete catalog with the pinned manifest and
performs the unchanged complete validation before showing course records. No
partially verified course DTO or cross-release detail fallback is used.

Plan a Round selects courses within the union of the chosen radius around current
committed origins. All pending nearby courses stay visible. Radius and documented
core filters apply; driving times remain unavailable. There is no routing POST,
provider request, modo area or matrix request, native admission, fake score or
completion witness in this public path. Enter/blur alone commits an address;
manual coordinates stay local. Normal public pages use existing Photon lookup and
OpenStreetMap tiles under the disclosed service policy. A restricted local preview
may block those hosts without changing the public asset source.

The user approved the native5 layout and functional preview on October 15, 2026.
Visual and text polish are subsequent work. Final source/data composition review,
required checks and actual hosted publication verification have their own evidence;
this contract does not claim deployment or acceptance of unfinished routing.
