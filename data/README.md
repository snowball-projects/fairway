# Catalog data authority

SQLite is the sole maintained facility/course catalog. Browser JSON is a generated,
immutable native read projection. Generated transport is never hand edited.
`data/catalog.json`, the old-schema browser reader and legacy publication commands
are retired. Accepted PR17 ancestry and all prior frozen review evidence remain
preserved; there is no old-schema runtime fallback.

The selected release is identified by
[`catalog-release/manifest.json`](catalog-release/manifest.json), which binds native
schema5, format2, exact revision, closed database SHA-256, counts and both compressed
and raw payload hashes/lengths. The sole writer supplies reviewed generated bytes.
The full database, SQL recovery snapshot, retained evidence and source controls stay
private. Public source code may include the native SQL schema, never the populated
recovery dump or evidence-bearing database. See the
[public contract](../PUBLIC-CATALOG-CONTRACT.md) and final release evidence.

## Generated public inputs

Only `data/catalog-release/manifest.json` and `catalog.json.gz` are public build
inputs. Export from an explicitly chosen closed native5 database using the native5
CLI, its exact closed binary SHA-256 and revision. Old schema4 is rejected; there is
no automatic upgrade or fallback to the older reader/export command.

```sh
PYTHONPATH=src python scripts/native5_catalog.py --db /private/closed.sqlite \
  export /private/new-export --sha256 CLOSED_BINARY_SHA256 --revision 760
```

The selected revision760 pins and accounting are in
[RELEASE760.md](../docs/catalog/RELEASE760.md). Schema4 export and migration tools
retained for historical tests are not the current native5 publication command.

After the sole writer reviews an immutable export, copy its exact generated manifest
and gzip. `scripts/build_pages.py` validates both, rejects private projection fields
and emits a content-hashed JSON asset. CI uses the same browser validator on the
complete catalog and compares two static builds. No browser SQLite engine or
editable JSON authority is introduced. Raw/gzip byte lengths remain recorded in the
manifest; browser memory, transfer and validation cost are not hidden by gzip size.

## Scope and unknowns

Facilities, course records, components, scoring rounds and tee sets remain distinct.
A component is not an independently bookable course. Shared canonical arrival
aliases are retained; property or address estimates remain qualified map context.
NULL means unknown. An empty observation array means no recorded observation.
Native map-context counts differ from legacy public-plus-positive-hole accounting.

All ten optional domains use the approved typed SQL columns and exact subject scope.
Course observations do not inherit facility facts. Source envelopes, dates, status,
conflict and qualifications remain attached. Dated prices retain conditions and are
not current quotes or comparable price rankings. Unknown architecture roles/years
stay unknown. Quality/star ratings remain empty; tee difficulty is not quality.
Remaining raw evidence is preserved privately and is not uniformly standardized or
used as a fallback. Public note provenance contains IDs only.

## Routing is separate

Public Pages selects catalog courses by straight-line distance around committed
origins. Driving times remain unavailable. No private routing transport, provider,
modo area/matrix, Spark execution or fake completion is connected. The separately
packaged eight-course Chicago API catalog and road snapshot remain unchanged and
do not provide a fallback for the national browser catalog.

## Road snapshot

`src/fairway/data/snapshots.json` binds a snapshot identifier to its artifact
file, release URL, checksum, cost profile, supported core, and graph bounds.

`chicago-static-v1.npz` is a compact road graph built from OpenStreetMap data.
It is distributed as a GitHub release artifact and is not tracked in source.

- Snapshot: `chicago-static-v1`
- Cost profile: `static-free-flow-seconds-v1`
- Created: August23, 2026 with OSMnx2.1.1
- Supported core: 41.8600077 to42.1699662 latitude,
  -88.1299989 to -87.6112705 longitude
- Graph bounds: 41.8500077 to42.1799662 latitude,
  -88.1399989 to -87.6012705 longitude. The supported core stays0.01
  degrees inside the graph on every side so accepted inputs are not on a hard
  extraction edge. This minimum halo does not prove that every ideal route
  outside the extract was retained.
- Graph: 63,413 vertices, 169,189 directed source edges, and166,843 stored
  minimum-cost edges after parallel-edge compaction
- Artifact: 2,603,992 bytes
- SHA-256: `c095461796adda233387c66f5b32c433c0d8a76d184902daf848fed1a3f2d39c`
- Source: OpenStreetMap contributors
- Data license: Open Database License1.0

The original GraphML checksum, extraction query, and road filter were not
retained, so v1 cannot be reproduced byte for byte. Future builds refuse
undocumented or invalid edge data and emit a checksummed build record:

```sh
uv run --locked python scripts/build_snapshot.py local-chicago.graphml \
  data/chicago-static-v2.npz \
  --source-url https://example.org/pinned-source \
  --source-date2026-08-31 \
  --extraction 'documented region or query' \
  --road-filter 'documented OSM road filter' \
  --generator 'OSMnx2.1.1 with documented command'
```

Replace the example values with the exact immutable source and commands used.
The builder requires a directed graph and a finite, positive `travel_time` on
every edge. Validate a release artifact and its course matrix with
`scripts/validate_snapshot.py` before publishing it.

The builder stages and rolls back the artifact and build record on ordinary
write failures, but two filesystem renames are not power-loss atomic. Published
snapshots must use a new immutable identifier and files; never rebuild over a
released pair in place.


Historical source-layer provenance is retained in [archived notes](../docs/catalog/LEGACY-PUBLIC-DATA.md).
