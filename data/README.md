# Catalog data authority

SQLite is the sole maintained facility/course catalog. Browser JSON is a generated,
immutable native read projection. `data/catalog.json`, the old-schema browser reader
and legacy publication commands are retired. Accepted PR17 research ancestry is
retained; no old-schema runtime fallback is supplied.

The current local release baseline is closed SQLite revision 758/native schema 4,
SHA256 `52ba61ecf5cc89dc5ee7212ec4a284dc3d3ccadf56f6171a108d770d27cf3fa9`.
Its full database, recovery SQL, evidence captures and control records stay private.
Only public native DTOs, source URLs, dates, licenses and qualifications are exported.
See [actual schema](../docs/catalog/SCHEMA758.md),
[release accounting](../docs/catalog/RELEASE758.md) and
[public seam](../PUBLIC-758-EXPORT-CONTRACT.md).

**This baseline is not publication-ready:** the approved relational optional-field
migration and independent review are pending. Core facility/course/access/style,
component/round/tee fields are typed. At 758 optional modules are sparse JSON, and
historical prose is not uniformly normalized. The public consumer does not infer
canonical prices, amenities or design credits from their raw keys. Quality/star
ratings are absent; tee difficulty rating means playing difficulty only.

## Generated public inputs

`data/catalog-release/manifest.json` and `catalog.json.gz` are exact generated bytes.
Never hand edit them. The manifest binds revision, native schema, closed database
release hash, row counts and compressed/uncompressed SHA256 and byte length.
Regenerate in a private workspace using an explicitly chosen closed database:

```sh
PYTHONPATH=src python scripts/export_native_catalog.py --db /private/closed.sqlite \
  --sha256 <closed-file-sha256> --revision <revision> --output /private/new-export
```

Review the export, then copy only its manifest and gzip. `scripts/build_pages.py`
validates both and emits a content-hashed native JSON asset. CI never needs private
SQLite or SQL recovery inputs. No browser SQLite engine or editable JSON catalog is
introduced. The 758 payload is 36,566,984 bytes raw /4,755,604 gzip; memory, bandwidth
and first-load performance need real browser review, especially on mobile.

## Counts and qualifications

The 758 baseline has 7,387 facilities, 3,641 retained course records and 2,144 shared
routing target records. Components and unresolved identities are labeled and are
not independently bookable-course claims. Empty inventories stay empty. Nulls mean
unknown. Public browse includes all access types; native map contexts total 4,640,
with 2,747 facilities not mapped. Legacy public+positive-hole accounting is 4,460;
that is a different predicate, not 180 additional facilities.

Compared with live f011e4, 758 adds 198 facilities and 672 retained course records:
573 records at existing facilities and 99 at 86 new facilities. The 672 comprise 664
operator-defined, 6 component and 2 unresolved records. 832 existing facility scopes
were enhanced. All records and source evidence from the original 7,204-facility
migration are retained. These are baseline counts pending canonical migration.

## Routing is separate

Public Pages only selects catalog courses by straight-line distance around committed
origins. Driving times are unavailable; no private routing transport is connected.
The separately packaged eight-course Chicago API catalog and road snapshot remain
unchanged. They do not provide a fallback for the national browser catalog.

## Road snapshot

`src/fairway/data/snapshots.json` binds a snapshot identifier to its artifact
file, release URL, checksum, cost profile, supported core, and graph bounds.

`chicago-static-v1.npz` is a compact road graph built from OpenStreetMap data.
It is distributed as a GitHub release artifact and is not tracked in source.

- Snapshot: `chicago-static-v1`
- Cost profile: `static-free-flow-seconds-v1`
- Created: August23, 2026 with OSMnx2.1.1
- Supported core: 41.8600077 to42.1699662 latitude,
  -88.1299989 to -87.6112705 longitude
- Graph bounds: 41.8500077 to42.1799662 latitude,
  -88.1399989 to -87.6012705 longitude. The supported core stays0.01
  degrees inside the graph on every side so accepted inputs are not on a hard
  extraction edge. This minimum halo does not prove that every ideal route
  outside the extract was retained.
- Graph: 63,413 vertices, 169,189 directed source edges, and166,843 stored
  minimum-cost edges after parallel-edge compaction
- Artifact: 2,603,992 bytes
- SHA-256: `c095461796adda233387c66f5b32c433c0d8a76d184902daf848fed1a3f2d39c`
- Source: OpenStreetMap contributors
- Data license: Open Database License1.0

The original GraphML checksum, extraction query, and road filter were not
retained, so v1 cannot be reproduced byte for byte. Future builds refuse
undocumented or invalid edge data and emit a checksummed build record:

```sh
uv run --locked python scripts/build_snapshot.py local-chicago.graphml \
  data/chicago-static-v2.npz \
  --source-url https://example.org/pinned-source \
  --source-date2026-08-31 \
  --extraction 'documented region or query' \
  --road-filter 'documented OSM road filter' \
  --generator 'OSMnx2.1.1 with documented command'
```

Replace the example values with the exact immutable source and commands used.
The builder requires a directed graph and a finite, positive `travel_time` on
every edge. Validate a release artifact and its course matrix with
`scripts/validate_snapshot.py` before publishing it.

The builder stages and rolls back the artifact and build record on ordinary
write failures, but two filesystem renames are not power-loss atomic. Published
snapshots must use a new immutable identifier and files; never rebuild over a
released pair in place.


Historical source-layer provenance is retained in [archived notes](../docs/catalog/LEGACY-PUBLIC-DATA.md).
