# Local facility query contract v1

`query_facilities(path, state=None, country=None, county=None, access=None, search=None, bbox=None, center=None, radius_km=None, limit=100, offset=0)` lives in `fairway.catalog_store`. The local transport command is `python scripts/sqlite_catalog.py --db LOCAL.sqlite facilities --state CA --limit 24`. This is a read function and JSON serializer, without a deployed HTTP endpoint, server or browser SQLite dependency. The API owner may expose its own coordinated transport after dependency review.

Response fields: `revision`, `facilities`, `limit`, `offset`, `total`, `has_more`, `qualification`. Every row, relationship, optional group, count and revision belongs to one SQLite read transaction. A consumer combining pages/regions rejects changed revisions and restarts the pool. Pagination limits match courses: 1..1000, default100; offset is nonnegative. Facility map IDs are f-UUIDs and are deduplicated separately from course IDs.

Each facility retains `facility_id`, `name`, `state`, `county`, `country`, `physical_holes`, nullable `inventory_complete`, `access`, `ownership`, `operating_status`, `website`, `website_status`, `website_checked_on`, booking/contact links, and original coordinate/address fields. `map_location` is `{latitude,longitude,kind}` or null. `address` is `{text,purpose,scope:"facility"}` or null. Missing values stay null; a property point never becomes a routing entrance in this DTO. `access_qualification` retains original accepted access-note text or null. Facility ownership/access labels do not certify its courses' booking eligibility.

`course_inventory` gives each retained record's `course_id`, nullable name/physical holes/nonmember booking fact, `identity_status` and `access`. `course_ids` and `course_count` cover all retained records. `documented_course_ids` and `documented_course_count` cover only `operator_defined` identities; component and needs_review records remain visible in the retained inventory with explicit qualifications. These counts describe stored records, not a certification of independent bookable inventories. A known empty stored list has count0 while actual physical inventory stays unknown/incomplete. Empty facilities remain map/context rows and produce no course card. The user's temporary unknown-inventory course-listing decision remains separate.

Native filters: exact state/country/county/access, literal substring search of facility name or its facility aliases, facility-map bbox SOUTH/WEST/NORTH/EAST (west>east supports antimeridian), and straight-line radius over facility map points using center LAT/LON + radius_km. Missing map points fail geographic filters. `access="unknown"` includes both SQL null and the explicit unknown enum. Search escapes `%`, `_` and backslash and uses SQLite LIKE's case behavior; it is not a fuzzy identity resolver. Text filters/search are limited to256characters. There is no Plan gate on facility context; course planning uses its separate ordinary-nonmember contract.

`fact_groups` contains only facility-scoped optional groups. Course-scoped groups appear through `query_courses`, which also includes inherited facility groups. Every group includes id, single facility/course parent, module, sparse object payload, source_id/source_url, collected_on, extracted/confirmed status, observed_on/effective_from/effective_to, and conflict boolean. Preserve these dates and scope beside displayed facts. Missing group/key, explicit null or an unrecognized shape means unknown. Booleans are known only when JSON true/false; a missing flag does not mean false. Do not derive flags from descriptions, price ranges, membership language or course names. Quality scores and publisher badges remain deferred.

## Current optional shapes at research revision21

These observations describe current transport, not hundreds of mandatory fields or a closed future schema. The importer validates module/object, core types/references and price currency/basis/observation requirements; it does not certify every optional payload key. Consumers should whitelist fields and validate their JSON types rather than coercing strings to numbers/booleans.

- `prices` (19groups): currency/basis strings; historical/current_rate booleans; source_information_as_of date string; green_fee_low/high and cart_fee_low/high numbers; cart_basis and qualification strings. Other observed fields include cart_included_in_green_fee boolean, pull_cart_fee number, junior_17andunder_green_fee number with junior_condition text, and before_1pm/after_1pm/senior_65plus_or_veteran objects with specific dated conditions. A directory's2025-12-01information date remains distinct from its2026-10-14collection/observation date. Do not show historical ranges as current/live quotes or use them as an unconditional visitor fee. Zero requires an explicit sourced free offer with its conditions. Future ordinary scalar `amount`/`minimum`/`maximum` fields are optional, not implied by existing ranges.
- `operations` (2groups): published_address_text, address_purpose, official_website and optional ownership strings. These are sourced statements, not routing entrance verification. No typed hours/seasons/maintenance facts exist in these current groups; those states remain unknown.
- `amenities` (0groups): current absence is unknown, not an all-false amenities inventory. Future typed booleans/counts need their own scoped source/date/status and known type before display/filtering. Practice/mobility/access facts in other modules must retain their actual scope and qualification.

Conflicts remain explicit; contradictory optional observations are not silently collapsed. Dynamic prices/hours retain their own observation/effective dates. The fixture files are pinned read-only examples, never a second catalog authority.
