Narrow native5 export validation correction, data unchanged

The frozen203f validator mistakes the two accepted Airway cart-price conditions
'Printed /ea with2riders per cart; ISOcurrency unknown.' for private paths.
This successor validates that notation only inside explicit per-person SQL price
conditions with the native price identity/observation/amount column shape.

The exception recognizes the exact /ea token in a leading printed shared-cart
rider clause, or after a leading monetary amount. Slash/path suffixes, extensions,
percent-encoded suffixes, query/fragment suffixes and separate paths still reject.
Generic qualifiers, location notes, dictionary keys and non-per-person price
conditions do not receive this exception. Normal HTTP tokens retain their prior
handling. No raw-source classifier, schema, intake, eligibility, reader or source
permission change is introduced.

Only the temporary validation scan changes; emitted operational text, all SQL
rows, source envelopes, currencies and billing basis are preserved byte for typed
value. No data wording is stripped or rewritten to make export pass. Private note
bodies remain SQLite-only. Existing closed760 and API dependency copies stay pinned
to203f; this successor requires its own independent narrow source review before
later publication. The actual immutable768 copy is used for the successful export
reproduction, while task18 independently reviews the frozen760-to768 fact delta.
